## 1. Код и проверка результата

- [ ] Выполнить обязательные требования выбранного кейса Voice Router и сопоставить каждое требование с реализованной функцией и результатом проверки.
- [ ] Проверить основной сценарий целиком: входные данные → обработка → результат, включая ошибки и доступный пользователю способ восстановиться после них.
- [ ] Проверить, что все видимые кнопки, показатели и данные связаны с работающей логикой; не выдавать заглушки за выполненную обработку.
- [ ] Сохранять завершённые значимые этапы отдельными коммитами и отправлять их в выданный командный репозиторий: `BAITC-Hacks/hack-6d253846-dir-echoes`.
- [ ] Перед финальной сдачей отправить последнюю версию и сверить локальный коммит с коммитом на GitHub.
- [ ] Зафиксировать реально выполненные проверки, известные ограничения и точный коммит сдаваемой версии.

Организаторы требуют итоговый код в выданном GitHub-репозитории и проверенный основной сценарий. Промежуточные коммиты и push предусмотрены рабочим процессом по требованию участника; минимальная частота коммитов в предоставленных правилах не установлена.

## 3. Данные, секреты и доступ

- [ ] Использовать официальный датасет организаторов для выбранного кейса. Участник подтвердил его использование.
- [ ] По умолчанию не включать исходные записи, архивы датасета и копии документов организаторов в Git или публичные каталоги приложения; описать способ подготовки данных отдельно.
- [ ] Не распространять исходный датасет. Загружать конфиденциальные, персональные или служебные данные во внешние сервисы только в пределах разрешения организаторов.
- [ ] Ограничить доступ к рабочим данным и истории обработки; исключить их появление в открытых логах и диагностических ответах.
- [ ] Сохранять API-ключи и другие секреты только в серверном окружении. Не помещать их в браузерный код, Git, README, презентации, чаты и снимки экрана.
- [ ] Исключить локальные файлы окружения из Git; в примере конфигурации оставить только имена переменных и безопасные пояснения.
- [ ] Перед каждым опубликованием проверить изменения на секреты и конфиденциальные данные.
- [ ] Сохранить ограничение доступа к репозиторию участниками команды и организаторами.
- [ ] При раскрытии ключа сообщить организаторам согласно их инструкции; для прекращения использования раскрытого ключа отозвать его и настроить новый через серверное окружение.
- [ ] После завершения мероприятия выполнить согласованное удаление временных ключей, токенов и локальных копий предоставленных данных.

Обычные проверки функций не должны превращаться в сканирование инфраструктуры хакатона или нагрузочные испытания без разрешения организаторов.

## 5. Личное участие

Участник принимает продуктовые и архитектурные решения, участвует в проверке результата и вносит личный вклад. AI-агент используется для разработки согласно инструкции организаторов. Участнику также необходимо соблюдать правила присутствия: не более 60 минут суммарных перерывов, присутствие в течение последнего часа и до официального завершения; выходы оформляются через стюарда.
