## 1. Подготовить сдаваемый коммит

1. Выполнить проверки для актуального дерева:
   ```bash
   pnpm typecheck
   pnpm test
   pnpm build
   git diff --check
   git status --short
   ```
2. Убедиться, что исходные JSON/PDF, локальные отчёты, базы, ключи и коды доступа не включены в Git. Полный `report.json` / `dev_subset.json` остаётся вне репозитория; в README достаточно агрегированных результатов.
3. Проверить README: текущие функции, команды, границы внешних интеграций, реальный URL или честный статус его отсутствия.
4. Создать финальный коммит и отправить в исходный репозиторий. Не переносить сдачу в другой репозиторий.
5. После push проверить совпадение:
   ```bash
   git fetch origin
   git rev-parse HEAD
   git rev-parse origin/main
   ```
6. Сохранить итоговый SHA и результаты проверок. Старый `ac18111` — подтверждённая промежуточная точка, а не автоматически финальная версия.

Участник требует последующие commit/push каждые 45–50 минут до 17:50. Предоставленные правила не устанавливают минимальную частоту коммитов; регулярный push не заменяет финальную форму сдачи.

## Текст для полей проекта

**Название:** DIR ECHOES — Voice Router для контакт-центра.

**Описание:**

DIR ECHOES принимает текст и голос на русском и казахском, включая смешанные реплики, и выбирает один или несколько из 40 сценариев контакт-центра через LLM. Сервер проверяет параметры, выполняет действия по официальному набору, сохраняет историю и требует подтверждения перед изменением бизнес-данных или созданием запроса доставки. Супервизор видит выбор сценария, альтернативы, действия и задержки; принимает обращения из очереди и продолжает диалог.

Стек: Next.js, TypeScript, PostgreSQL / Neon, OpenAI Structured Outputs, STT и TTS, Vercel. На 104 открытых dev-репликах получено 95,19% верного основного сценария и 93,27% полного совпадения. Это оценка текстового router; она не заменяет живую проверку речи. Платёжные, SMS, телефонные и клинические подключения не предоставлены: система сохраняет реальные запросы и явно показывает ожидание внешнего исполнения.

Перед вставкой сверить описание с финальным коммитом. Результаты публикации и живого голоса дописать только после их проверки.
