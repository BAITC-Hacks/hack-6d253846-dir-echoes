## Подготовка окружения

1. Установить Node.js 22+ и pnpm, получить доступ к командному репозиторию и официальному архиву кейса.
2. Выполнить `pnpm install --frozen-lockfile`.
3. Создать `.env.local` по `.env.example`. Указать OpenAI-ключ, разные коды ролей длиной от 8 символов и случайный `SESSION_SECRET` длиной от 32 символов.
4. Выбрать базу: `DATABASE_URL` для PostgreSQL / Neon либо локальная PGlite для разработки. При наличии `DATABASE_URL` она имеет приоритет над `LOCAL_DATABASE_PATH`.
5. Распаковать официальный набор вне репозитория. `DATASET_PATH` указывает непосредственно на каталог JSON, без `__MACOSX`.
6. Выполнить `pnpm launch`: подготовка данных, сборка и локальный запуск выполняются одной командой. Адрес — [localhost:13300](http://localhost:13300), либо порт из `PORT`. Для разработки с обновлением кода используйте `pnpm db:import`, затем `pnpm dev`.

`pnpm launch` работает после установки зависимостей и заполнения окружения. Если `DATASET_PATH` задан, выполняется идемпотентный импорт; иначе нужен уже импортированный каталог. При отсутствии `DATABASE_URL` используется `.data/postgres` либо явный `LOCAL_DATABASE_PATH`. Launcher закрывает соединение подготовки до запуска Next.js, проверяет занятость порта и не завершает чужие процессы. Платные AI-вызовы при запуске не выполняются. Для Vercel остаётся штатная сборка платформы с внешней PostgreSQL.

После импорта приложение читает каталог из базы. Файловый `DATASET_PATH` нужен для импорта, корпусных тестов и evaluator; он не нужен runtime на Vercel. Для оценки также нужны `dev_utterances.json` и предоставленный `evaluate.py`.

Дата бизнес-правил читается из `scenarios.json → meta.as_of_date`. Сейчас это 2026-10-01.

Схема создаётся при первом обращении к базе через `ensureDatabase()`. Отдельной команды миграций сейчас нет. Импорт той же версии идемпотентен и не восстанавливает изменённые записи поверх текущих. Новый хеш набора отклоняется: изменение версии требует отдельной миграции с сохранением истории.

## Хранение

| Таблица | Содержимое |
| --- | --- |
| `dataset_versions` | Импортированный каталог, база знаний, исходный набор и SHA-256 |
| `sessions` | Владелец, состояние, версия, блокировка обработки и время обновления |
| `turns` | Реплики, ответы, trace, статус обработки, уникальный request ID в разговоре |
| `entities` | Клиенты, полисы, заявления, платежи и новые сущности по полям kind/id |
| `handoffs` | Очередь, причина, контекст, waiting/active/closed |
| `operator_commands` | Идентификатор команды оператора, автор, хеш содержимого и сохранённый результат для безопасного повтора |
| `rate_limits` | Ограничения частоты |
| `review_annotations` | Ручная оценка основного сценария и комментарий к завершённой LLM-реплике |
| `catalog_revisions` | Версии названий, описаний, примеров и границ сценариев, автор и цепочка хешей |
| `speech_audio` / `speech_content_leases` | Кэш озвучивания и защита от одновременных повторных TTS по содержимому |
| `ai_budget_days` / `ai_budget_ledger` | Общий журнал оценочных затрат, резервирование и закрытие вызовов AI |

Сиды используют виды `clients`, `policies`, `claims`, `payments`. Исполнитель дополнительно сохраняет `operations`, `outbox`, `complaints`, `callbacks`, `disputes`, `appointments`, `inspections`, `fraud`.

Действие, его результат и состояние разговора фиксируются транзакцией. LLM вызывается вне транзакции; перед изменением проверяется версия разговора. Ответ исполнителя сохраняется до необязательной дополнительной формулировки, поэтому ошибка этого этапа не отменяет уже выполненное действие и не требует повторного исполнения.

## Вход и доступ

- `participant`: собственные разговоры в текущей браузерной идентичности, их история, трассировка и экспорт.
- `supervisor`: общая история и обращения, принятие запроса, сообщение клиенту и закрытие; оценка маршрутов и редактирование допустимых текстовых полей каталога.
- Авторизованная сессия действует 12 часов; отдельная подписанная cookie хранит идентичность браузера до 30 дней.
- После удаления cookie или входа с другого браузера создаётся другая идентичность. Это не система персональных аккаунтов с восстановлением доступа.
- Изменяющие API-запросы проверяют Origin. Cookie имеют HttpOnly и SameSite Strict; в production также Secure.
- Супервизорский код передаётся только тем, кому разрешён общий доступ. Коды не включаются в README, скриншоты и форму публичного описания.

## Голос

**Готовящийся пакет после `a3313b8`:** ниже описаны новый измеритель TTS по копии MP3 и отдельный звёздный фон. Они ещё ожидают нового деплоя и приёмки. Сбой уточнён пользователем: **desktop Codex IAB молчит при автоматическом ответе и при ручном «Слушать ответ»**. Его устранение пока не подтверждено.

Новый режим запускается кнопкой **«Начать разговор»**. Браузер запрашивает микрофон, выделяет реплики локальным детектором энергии и автоматически отправляет завершённую фразу после **950 мс** тишины. Затем выполняются STT, маршрутизация, действие и потоковый TTS; после ответа прослушивание возобновляется без повторного нажатия. STT получает отдельные файлы, потокового входного распознавания и реального телефонного соединения нет.

В [use-voice-call.ts](../src/lib/use-voice-call.ts) используются RMS и адаптивный порог шума. При запуске около **320 мс** занимает оценка фона — «Настраиваю микрофон» (`calibrating`); после ответа около **250 мс** занимает восстановление — «Включаю микрофон» (`settling`). Буфер начала фразы составляет **500 мс**, минимальная голосовая активность — около **60 мс**. Локальный PCM сохраняется во время этих коротких окон, чтобы можно было восстановить уже закончившееся короткое «да / иә / evet». Дождаться готовности особенно важно при первой настройке: непрерывная речь во время всей калибровки может завысить оценку фона. Музыка, громкие импульсы, тихая речь и паузы внутри фразы всё ещё требуют человеческой проверки; этот VAD не является классификатором речи и шума.

Во время обработки и воспроизведения аудиозатвор микрофонной записи закрыт. Кнопка **«Перебить ответ»** вручную останавливает озвучивание; автоматического перебивания голосом/full-duplex нет. **«Завершить звонок»**, переход к тексту, смена экрана/разговора, скрытие вкладки и уход со страницы останавливают дорожки микрофона. Это кнопка браузерного режима: телефонный звонок внешнему абоненту не создаётся. Уже сохранённое бизнес-действие остановкой звука не отменяется.

Ограничения входа: файл до 3 МБ, запись до 45 секунд. Новый recorder выбирает поддерживаемый WebM/Opus, WebM или MP4; сервер также принимает предусмотренные API форматы MP3/WAV. Ответ озвучивается голосом `coral`. Текстовая история остаётся доступной при отказе голосового сервиса.

Органичная форма до **3400 частиц Canvas** (**1800** на мобильных) использует реальный `micLevel` при прослушивании/речи и RMS декодированной копии ответа из [use-playback-meter.ts](../src/lib/use-playback-meter.ts), синхронизированный с `audio.currentTime` примерно **15 раз в секунду**. Активная форма крупнее: прослушивание собирает её, ответ раскрывает. Эти переходы обозначают состояние, отдельно от измеренного уровня; они не имитируют RMS. Светлая тема использует контрастный графит. Отдельный [звёздный фон](../src/components/background-starfield.tsx) занимает весь viewport: **180** звёзд на больших экранах / **110** на мобильных, без реакции на голос и курсор. Физическую слышимость и правильность текста анимация не доказывает.

Новый UI построен вокруг чёрной голосовой сцены с мобильной компоновкой навигации и управления разговором. Кнопка **«Чат»** открывает прозрачный слой расшифровки и текстового ввода; **«Весь разговор»** показывает полную переписку вместо последней реплики. **«Подсказки»** управляет контекстом: текущей темой, необходимым подтверждением, передачей оператору и отложенными вопросами. Через **«Показать логику ответа»** открывается trace; его данные сохраняются и при скрытой панели. При отсутствии сохранённого выбора применяется **тёмная тема**. Светлая/тёмная тема выбирается на входе или в верхней панели и сохраняется в `localStorage`; если браузер запрещает хранилище, переключение работает до перезагрузки. Проверка размеров в браузере подтверждена для 390×844, 390×500 и 844×390; реальное поведение клавиатуры ОС/Safari требует отдельной приёмки.

Подготовка нативного звука выполняется в пользовательском нажатии: `unlockAudioPlayback(audio)` запускает локальную тишину. Этот же постоянный `HTMLAudioElement` используется для ответов и ручного прослушивания. `usePlaybackMeter.prepare(audio)` только привязывает обработчики измерения; звуковой граф, `resume()` и `MediaElementSource` не создаются. MSE начинает воспроизведение до окончания загрузки; при отсутствии поддержки используется Blob того же ответа. Проверки отмены и поколения защищают от позднего завершения старого запроса; ожидание событий MSE ограничено 15 секундами.

Измеритель декодирует копию **полного MP3** через `OfflineAudioContext` и читает рассчитанный RMS по текущему времени аудиоэлемента. Во время незавершённого MSE-потока, до EOF и декодирования копии, уровень остаётся **0**. Ошибка необязательного декодирования тоже даёт ноль. Анализатор не подключается к динамикам и не управляет нативным воспроизведением; при скрытии вкладки/размонтировании останавливаются только измерение и его обработчики. Голосовой режим отдельно владеет остановкой микрофона и звука. Autoplay-политика браузера и физическая слышимость требуют отдельной проверки.

Новый языковой контракт допускает RU, KK, TR и смешанную речь. Массивы `inputLanguages` / `responseLanguages` сохраняют фактическое сочетание: RU/KK, RU/TR, KK/TR либо все три языка. Старые записи `mixed` без массива трактуются как RU/KK. Это контракт реализации; измеренного качества турецкого языка и его смешанных сочетаний пока нет. Исходные примеры каталога и редактируемые примеры остаются RU/KK.

`STT_FALLBACK_MODEL` — необязательная резервная модель, если основной STT недоступен. Она не меняет автоматически модель при каждом неудачном пользовательском вводе. Смена модели требует повторной проверки казахского и смешанного языка.

Кэш TTS привязан к сохранённой реплике и тексту. Повторное воспроизведение готового ответа не обязано создавать новый платный синтез. Задержка первого аудиобайта, серверная обработка и фактическое начало воспроизведения — разные показатели.

Серверный ответ TTS передаёт аудио по мере поступления и сохраняет результат в кэш только после полного получения. Отменённый или оборванный поток не считается полным кэшем. Проверьте начало слышимого воспроизведения отдельно: наличие серверного потока, реакции частиц и прежнее событие `onplaying` не доказывают работу нового режима с человеческим микрофоном или достижение 1,5 секунды от конца речи.

## Супервизия и ручное исполнение

Оценка маршрута доступна для завершённых LLM-реплик. Укажите ожидаемый основной сценарий и комментарий. Панель показывает объём ручной выборки, согласие с оценкой и задержки по источнику; эти числа не следует выдавать за точность всего входящего потока.

Каталог позволяет редактировать только название, описание, RU/KK-примеры и правила исключений существующих сценариев. Сохранение требует актуального хеша; при конфликте загрузите новую версию и повторите правку. История версий сохраняется, исходный импорт организатора остаётся отдельным.

При подтверждённом запросе приёма, осмотра или обратного звонка оператор получает связанное обращение с номером бизнес-запроса. Примите обращение, согласуйте внешнее исполнение и зафиксируйте результат сообщением. Закрытие очереди не является автоматическим бронированием, звонком или подтверждением оплаты. Outbox с `provider_not_configured` остаётся запросом доставки без подключённого провайдера.

Интерфейс передаёт обязательный стабильный `requestId` для команды оператора. Если ответ потерян из-за сети, повтор с тем же идентификатором, автором, статусом и текстом возвращает сохранённый результат; повторная реплика не создаётся. Использование идентификатора с другим содержимым возвращает 409. Закрытие временно отклоняется, пока сохраняется клиентская реплика, чтобы она осталась в истории. После обновления приложения старые вкладки нужно перезагрузить перед отправкой операторских команд.

## Расходы API

`MAX_AI_SPEND_USD` задаёт суточный предел **оценки приложения**, от 0,05 до 50 USD, по суткам UTC. Общая БД резервирует оценку перед каждым router/response/STT/TTS-запросом. После получения usage оценка уточняется. Неопределённый исход API не освобождает резерв автоматически: провайдер мог списать оплату.

Для стандартного router заданы ставки по умолчанию. При другой модели требуется явно указать `ROUTER_INPUT_USD_PER_MILLION` и `ROUTER_OUTPUT_USD_PER_MILLION`. Для речи предусмотрены настройки `STT_USD_PER_MINUTE` и `TTS_ESTIMATED_USD_PER_MINUTE`; оценочные ставки должны соответствовать выбранному провайдеру и модели.

Этот механизм не является лимитом OpenAI Billing. Окончательный счёт, неизвестный usage и оценки длительности речи могут отличаться. У evaluator дополнительно есть собственный `--max-usd`; он также является оценочным ограничением.

Команды ниже — инструкции для отдельного запуска, а не журнал их выполнения.

```bash
pnpm typecheck

pnpm evaluate --limit 104 --concurrency 2 --max-usd 1 --out reports/routing-check
```

Оценка делает реальные вызовы и не запускается без явного `--limit`. Параллельность — не более двух, автоматических повторов нет. Полный отчёт содержит исходные примеры в `dev_subset.json`; каталог результата сохраняется локально и не публикуется.

Для runtime после сборки:

```bash
pnpm start
```

Стандартный production-порт Next.js — 3000, если серверное окружение не задаёт другой. Для локального production-запуска PGlite необходимо явно настроить `LOCAL_DATABASE_PATH`; для Vercel всегда нужна PostgreSQL.

Ручная приёмка опубликованной версии:

1. Войти участником, создать разговор, задать информационный вопрос; открыть «Подсказки» → «Показать логику ответа» и проверить trace.
2. Взять разрешённый профиль из оригинального набора, получить preview изменения и убедиться, что до подтверждения оно не выполнено.
3. Подтвердить действие, перезагрузить страницу и проверить сохранение результата; повтор запроса не должен создавать ещё одну операцию.
4. Попросить оператора, войти супервизором в отдельной браузерной сессии, принять обращение, ответить и закрыть.
5. В опубликованном `a3313b8` нажать «Начать разговор» один раз, произнести RU, KK и смешанную реплики с паузами; проверить автоматическую отправку, транскрипцию, язык, смысл и слышимость. Проверить «Перебить ответ», возобновление прослушивания и остановку микрофона при завершении/смене экрана/скрытии вкладки. Отдельно принять добавленный TR и заявленные сочетания с TR; не переносить на них прежние RU/KK-оценки.
6. Проверить отказ в доступе к чужому разговору для участника и доступ супервизора согласно роли.
7. На мобильной ширине проверить навигацию, управление голосом, прозрачный чат, ввод и закрытие панелей; переключить тему и перезагрузить страницу. Без сохранённого выбора должна появляться тёмная тема. Раскрыть полную историю, подсказки и trace; для фактически отложенной темы проверить перенос вопроса в текстовый ввод и продолжение после отправки.
8. На desktop Codex IAB повторить автоматическое озвучивание и ручное «Слушать ответ»: пользователь сообщил о тишине в обоих случаях. Зафиксировать физическую слышимость, затем проверить короткие ответы после `calibrating` / `settling`. RMS частиц ожидается только после полного получения и декодирования копии MP3; во время незавершённого потока или паузы нулевой уровень допустим. Исправление считать принятым после слышимого повторения обоих путей.

## Vercel + Neon

В проекте Vercel нужны Next.js и Node.js runtime. Укажите серверные переменные отдельно для Production и Preview, если используется preview-деплой. Импорт выполните из локального окружения с `DATABASE_URL` целевой Neon-базы. Не загружайте исходные JSON в `public/` и не встраивайте их в клиентский пакет.

После изменения секретов или строки БД нужен новый деплой, использующий эти настройки. Подтверждение готовности: статус `Ready`, проверенный URL и ручной сценарий. `GET /api/health` не проверяет импорт, БД, API модели или голос.

Production URL: [dir-echoes-voice-router.vercel.app](https://dir-echoes-voice-router.vercel.app). Публикация выполняется через Vercel CLI: автоматическое подключение приватного GitHub-репозитория не удалось, поэтому push сам по себе не обновляет приложение. После изменения кода отдельно выполните `pnpm dlx vercel@59.25.0 --prod --yes` из связанной рабочей копии и дождитесь Ready. Команда использует Vercel CLI из официального npm-пакета и требует входа в нужную команду Vercel. Последний проверенный деплой указан в [контрольных точках](CHECKPOINTS.md).

## Диагностика без раскрытия секретов

| Симптом | Проверка |
| --- | --- |
| «Данные ещё не импортированы» | Правильная целевая БД и успешный `pnpm db:import` |
| «Постоянная база данных ещё не настроена» | Серверная `DATABASE_URL` в нужном окружении Vercel |
| Ошибка входа | Выбранная роль и её код, длина SESSION_SECRET, cookie и лимит попыток |
| Достигнут дневной AI-лимит | Настройка лимита, журнал резервов и расход у провайдера |
| STT недоступен | Доступность указанной модели и формат записи; временно продолжить текстом |
| TTS недоступен | Сохранённый текст ответа, доступ к модели и ограничение частоты |
| Текст ответа есть, но звук не начинается | Повторить «Слушать ответ» явным нажатием на том же устройстве; записать имя ошибки autoplay/декодирования. На мобильном браузере проверить, что вкладка активна и контекст возобновился. Повтор не означает обязательного нового платного синтеза |
| Реплика обрывается или шум отправляется как речь | Дождаться окончания первой настройки; записать обстоятельства, язык, краткость ответа, фон и длительность паузы. Проверить локальный VAD; музыка и резкие звуки могут дать ложное срабатывание |
| После ответа микрофон не возобновился | Состояние воспроизведения и ошибки браузера; завершить режим и начать снова. Не считать индикатор доказательством работающей записи |
| Звук слышен, но частицы не реагируют | При незавершённом MSE-потоке уровень ещё неизвестен. После EOF проверить поддержку OfflineAudioContext, декодирование копии и видимость вкладки; ошибка измерителя не должна прерывать звук или запускать новый TTS |
| Операция остаётся queued / request_pending | Это ожидаемое состояние без внешнего сервиса доставки / расписания |
| Новый набор не импортируется | Хеш отличается; нужна явная миграция, а не стирание текущих записей |

В логах не печатать строки подключения, коды доступа и API-ключи. При передаче диагностики достаточно статуса, времени, request ID и обезличенного сообщения ошибки.
